# Data Model: режим ожидания оценок

Схема БД **не меняется**: всё нужное уже есть (миграция
`migrations/versions/2025-12-14_update_models_according_to_requirements.py`).

## Users (существующая таблица, используемые поля)

| Поле | Тип | Смысл | Правило |
|---|---|---|---|
| `id` | BIGINT PK | пользователь Telegram | — |
| `watch_mode_expires_at` | TIMESTAMP NULL | до какого момента действует режим; `NULL` — выключен | при включении/продлении = `now() + WATCH_MODE_MINUTES`; проверка активности: `> now()` |
| `watch_mode_last_sync_at` | TIMESTAMP NULL | время последней проверки в режиме | обновляется циклом; при выключении/истечении — `NULL` |
| `is_authenticated` | BOOL | есть действующая авторизация | включение запрещено при `false` |
| `group_id`, `group_name` | BIGINT/STR | группа для группового кеша журналов | не меняются |

Индекс: существующий по `group_id`; для выборки ожидающих достаточно условия по
`watch_mode_expires_at` (объём — сотни строк, отдельный индекс не вводим; если появится
медленный запрос, добавляется отдельной миграцией).

## Redis: `watch_mode:users`

| Свойство | Значение |
|---|---|
| Тип | SET |
| Члены | `user_id` пользователей в режиме |
| TTL | **нет** — единственное исключение из правила TTL (ARCHITECTURE §4.2) |
| Кто пишет | включение/продление (`SADD`), выключение (`SREM`), уборка (сверка с БД) |

## Состояния режима у одного пользователя

```text
        enable (требует is_authenticated)
  ┌────────────────────────────────────────────┐
  ▼                                            │
ВЫКЛЮЧЕН ──enable──▶ АКТИВЕН ──extend──▶ АКТИВЕН (срок = now + 30 мин)
  ▲                     │
  │                     ├──expire (now > expires_at)──▶ ВЫКЛЮЧЕН
  ├──disable────────────┘
  └──cleanup (идемпотентно, в т.ч. для уже выключенного)
```

Переходы и инварианты:

1. `ВЫКЛЮЧЕН → АКТИВЕН` требует `is_authenticated = true`; иначе отказ, состояние не меняется.
2. `АКТИВЕН → АКТИВЕН` (enable повторно) = продление, а не ошибка.
3. `АКТИВЕН → ВЫКЛЮЧЕН` по времени: `expires_at <= now()`; `watch_mode_expires_at` и
   `watch_mode_last_sync_at` обнуляются, `SREM` из множества.
4. `АКТИВЕН → ВЫКЛЮЧЕН` по действию пользователя: то же, немедленно, проверки прекращаются.
5. Инвариант: не более одной активной записи на пользователя (это поле, а не таблица).
6. Инвариант: `watch_mode_last_sync_at` никогда не позже `now()` и обновляется только циклом.
7. Инвариант: отрицательного остатка не бывает — остаток `max(0, expires_at - now())`,
   при нуле показывается «режим выключен».

## Сущности из спеки → где живут

| Сущность спеки | Реализация |
|---|---|
| Режим ожидания пользователя | `users.watch_mode_expires_at`, `users.watch_mode_last_sync_at` |
| Список ожидающих | `watch_mode:users` (индекс) + выборка из `users` (истина) |
| Запись истории синхронизации | `sync_logs` с `sync_type = watch_mode` |
| Пользователь, Оценка | существующие `users`, `grades`, `journals` — не меняются |

## Валидация (из требований спеки)

- `WATCH_MODE_MINUTES > 0` и `>= WATCH_MODE_TICK_MINUTES` — иначе режим истекает раньше
  первого цикла (проверяется при старте настроек).
- `WATCH_MODE_TICK_MINUTES` делит 60 без остатка (5, 10, 15, 30) — иначе `crontab(minute="*/N")`
  даст неровный шаг.
- Длительность и шаг — из `Settings`, не из литералов в коде (принцип III).
